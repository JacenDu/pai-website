Client integration ​

A PAI client exchanges requests with a selected PAI service. A personal AI application or Harness can invoke the supplied CLI, import the publication helper, or implement the HTTP operations directly. This guide describes the content profile 0.1.0-draft.1; the service specification defines its requirements.

Select a service and credential ​

Configure the service origin and obtain a publisher credential from that service. Use an HTTPS origin for a network deployment. The reference client also accepts HTTP on loopback addresses.

sh
export PAI_SERVICE=http://127.0.0.1:4747
export PAI_TOKEN='replace-with-the-credential-issued-by-this-service'

Public reads do not require the token. Publication and updates send it as Authorization: Bearer .... The server determines publisherId from that credential. An author name in the document does not establish publishing rights.

The reference client accepts an origin, such as https://pai.example, rather than a path-prefixed base URL. Its HTTP helper rejects redirects and links to another origin, and sends the credential only with a write request.

Discover operations ​

Read the fixed discovery entry point:

sh
curl --fail --silent --show-error "$PAI_SERVICE/.well-known/pai.json"

Check protocol, version, profile, capabilities, formats, and authentication. Follow the returned endpoints and subsequent resource links. Endpoint paths in examples are illustrative; a compatible server may use different paths.

The current client requires content model 0.6 and recognizes pai-zip-v1 and pai-html-v0.6. It reports an unsupported protocol version or missing required capability before writing.

Publish a file ​

Run from the PAI project directory:

sh
npm run publish -- "$PAI_SERVICE" content/dist/event.pai
npm run publish -- "$PAI_SERVICE" content/dist/event.pai.html

The CLI discovers the service and sends the file bytes. Its JSON output contains status, the returned resource, and resolved links.reading, links.content, and links.download URLs. Save the resource URL and publication version with the result of the user task.

For the same publisher, document ID, revision, and content, the second command is a retry. It returns 200 and the existing snapshot even though the container changes. The first successful publication returns 201. The download remains the file first stored for that snapshot.

HTTP request example ​

After discovery, assign the returned publication URL to PAI_DOCUMENTS_URL. For the local reference server the URL is http://127.0.0.1:4747/documents:

sh
PAI_DOCUMENTS_URL=http://127.0.0.1:4747/documents
curl --fail --silent --show-error \
  -H "Authorization: Bearer $PAI_TOKEN" \
  -H 'Content-Type: application/zip' \
  --data-binary @content/dist/event.pai \
  "$PAI_DOCUMENTS_URL"

An HTML upload uses Content-Type: text/html; charset=utf-8 and the .pai.html file. The request body contains the file itself. It has no JSON wrapper or Base64 transport layer. Validate the resolved URL against the selected origin before attaching credentials in a client implementation.

JavaScript integration ​

The helper is shipped as source and runs under Node.js 24. Save this example as an .mjs file in the PAI project directory:

js
import { readFile } from 'node:fs/promises';
import { publishFile } from './src/publication-client.ts';

const result = await publishFile(
  'http://127.0.0.1:4747',
  await readFile('content/dist/event.pai'),
  process.env.PAI_TOKEN,
);
console.log(result.links.reading);

For an update, pass the selected resource URL as the fourth argument. The helper reads that resource, follows its updateUrl, and sends a PUT request.

Update a selected resource ​

Edit the document in the browser or with the file CLI, then save the changed file. Use the resource.url returned by publication:

sh
npm run publish -- "$PAI_SERVICE" edited.pai \
  --update http://127.0.0.1:4747/resources/RESOURCE_ID

Replace the example resource URL with the actual response URL. The selected resource must belong to the credential's publisher and have the same document ID as the uploaded file. A new document revision creates the next publication version. Changing content while reusing a previously published revision produces 409 document_revision_conflict.

An already published historical revision can be retried and returns its saved snapshot. This does not move the latest-version pointer backwards. A lower, never-published revision produces 409 stale_document_revision.

Updates upload the complete changed file. Local block patches and binary image editing do not change the HTTP request body or provide network delta transfer.

Retrieve content and preserve sources ​

The public retrieval CLI lists the service catalogue when no document is selected:

sh
node src/read.ts "$PAI_SERVICE"
node src/read.ts "$PAI_SERVICE" --publisher tester:alice --document event
node src/read.ts "$PAI_SERVICE" --resource http://127.0.0.1:4747/resources/RESOURCE_ID

Use the actual resource URL returned by the selected service. Selection by publisher and document ID requires exactly one match; the tool reports a missing or ambiguous match. Titles do not establish document identity.

A selected read returns JSON with service, resource, ordered blocks, and assets. Source URLs are resolved against the service origin. Normal text reads fetch metadata and structured content; they do not download the original file or renderer. The CLI never sends a publisher credential, even when PAI_TOKEN is present in the caller's environment.

Read a previous publication version or extract an original image:

sh
node src/read.ts "$PAI_SERVICE" --publisher tester:alice --document event --version 1
node src/read.ts "$PAI_SERVICE" --publisher tester:alice --document event \
  --asset hero --output hero.svg

--version identifies a service publication version, not a document revision. The client follows the service's previous-version links. Image extraction downloads the selected version's original file, reads its declared container, checks its identity and content hash, and writes the original asset bytes. The output must be a new file. Asset results add its ID, MIME type, byte count, SHA-256, and output path to the JSON response. Public reads and image extraction use the same HTTPS-or-loopback origin and same-origin link rules as the publication client.

Use the following sequence when another user asks their AI to reuse published material:

  1. Read endpoints.resources from discovery. The catalogue returns { "items": [...] }.
  2. Select the resource by its ID or known URL. For a known document, match the intended publisher and document.id; titles may repeat.
  3. Read that resource and retain versionUrl. Follow representations.content for ordered Markdown blocks and image metadata.
  4. Use each selected block's sourceUrl as its source link. Retain the resource ID, publication version, document ID, and document revision with the extracted material.
  5. Fetch representations.download when original images or the full document are needed. Read it according to downloadFormat.

representations.content returns {resource, document, blocks, assets}. It omits image encoding and editor code. A block with a background image has a backgroundImage reference. Images referenced by multiple blocks share an asset ID; block source links identify their locations.

The original file may be ZIP or HTML. Verify its document ID and revision against the selected snapshot, then obtain images by asset ID. For example:

sh
node content/cli.mjs inspect downloaded.pai
node content/cli.mjs text downloaded.pai
node content/cli.mjs text downloaded.pai intro
node content/cli.mjs asset downloaded.pai hero -o hero.svg

The same commands accept .pai.html. The file parser reads embedded data without executing scripts. Image extraction currently requires the full original download; the content profile has no individual-image endpoint.

text emits Markdown in layout reading order, optionally selecting a block. It retains pai: image references. For direct JavaScript integration, readPaiFile() returns a validated document whose image data values are Uint8Array. Use getAsset() for a detached byte copy and toJSONDocument() when serializing the complete document as JSON. readMarkdown() and inspectDocument() extract from the loaded document without accessing image data. See the file API guide.

The reading representation presents the selected snapshot. Its editor can produce a locally modified file. Saving that file does not publish it; publication remains a separate authenticated operation.

Handle errors ​

Use the HTTP status and JSON error value, rather than matching human-readable messages. Common cases are 401 for absent or invalid credentials, 403 forbidden for another publisher's resource, 409 for a revision or document-ID conflict, and 415 unsupported_format for an unsupported input. The complete table is in Service behavior.

Do not automatically assign a new document ID or revision after a conflict: that changes the meaning of the user's update. Read the current resource, compare the intended document revision, and apply the application's explicit retry or merge policy.

Exercise an integration ​

Use the service checker to inspect a deployment through its declared interfaces. It supports public reads and authenticated publication, retries, updates, and historical reads. Use the public retrieval CLI above for content access.
