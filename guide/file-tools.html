PAI file tools and browser editor ​

This directory implements content model 0.6 for both PAI file forms. A .pai file contains document data and original images in a ZIP container. A .pai.html file carries the same content together with rendering and editing code for independent browser use.

The Node CLI, browser editor, and reference service share the file parser and validation rules. File specification · Client integration · Service integration

Build and open ​

Run these commands in the content/ directory:

sh
npm ci
npm run build
npm test

After building, open dist/service.pai.html, dist/event.pai.html, or dist/guide.pai.html in a browser. The build also produces the project Dashboard at dist/dashboard.pai.html. These generated files are excluded from Git. The optional reading comparison has a separate build command.

The Dashboard uses the same content model and editor as the examples. Its maintained input is development/dashboard/dashboard.mjs at the project root, with figures in development/dashboard/dashboard-figures/. Browser edits are saved as local downloads; they do not modify the maintained source file.

Edit a document ​

The current editor uses Chinese labels. 编辑 enters editing, and 完成 hides the editing controls. An active block has a light boundary; text paragraphs have no separate inner focus frame.

ActionControl
Move or configure an entire blockHandle at the top center of the block
Add a paragraph, heading, list, quote, code, image, or table after the current contentPlus button beside the content
Add an independent blockInsert control between blocks or at the end of the document
Format selected textFloating toolbar; </> applies inline code and the paragraph-type menu selects a code block
Move the floating toolbarDrag its left handle; selecting new text restores automatic positioning
Resize an imageDrag a corner, preserving aspect ratio
Move an imageDrag the handle at its upper-left corner between paragraphs or blocks
Align or replace an imageImage toolbar, with left/center/right alignment and replacement controls
Use an image as a block backgroundImage toolbar, then adjust crop position and overlay in the block menu
Change a block's background color or blank spaceBlock settings; empty paragraphs provide blank vertical space

In a multi-column layout, the content plus button has priority in its hit area. Adjacent gaps remain available for column resizing. Image placement changes update layout parameters without re-encoding the original image.

The top bar provides undo, redo, edit/done, save, new, and details. 详情 (Details) contains page color, narrow-screen preview, a document prompt for AI, shortcuts, and application information. Performance measurements and raw JSON are development outputs.

Markdown-style input supports heading, list, and quote prefixes. Bold, italic, inline-code, and link syntax converts after a space. Type / on an empty paragraph to add content, or three backticks followed by Enter to start a code block. Editing remains in the document view.

Open, save, and export ​

Choose 新建 → 打开现有文件 (New → Open existing file) to import .pai or .pai.html. An unsuccessful or cancelled import leaves the current document in place. If it has unsaved edits, opening another document first asks how to handle them.

保存 → 保存 .pai, or Cmd/Ctrl+S, generates a .pai download. 保存 → 导出独立 HTML generates a standalone .pai.html. Print/PDF and experimental Markdown export are in the same save menu. Downloaded filenames include the document ID and revision.

The status 已生成下载 means the browser received the download. The browser controls its location and retention. Saving preserves all images in the asset table, including images not currently referenced by a block. Editing while an asynchronous save is running leaves those later changes marked as unsaved.

Creating a blank document offers 保存并新建 (Save and create). The new document opens after the download is generated. If editing continues during that save, the current document and its unsaved changes remain open.

A standalone HTML file contains the editor version used at export time. To use a later editor, open the old document in the current editor and export it again. A supported browser can read, edit, and save the standalone file offline. Attachment previews that do not execute scripts cannot render the current file; download it and open it in a browser.

Saving from a published reading page also creates a local download. Use the publication client to upload an update. Existing version links continue to identify the previously published content.

AI and programmatic editing ​

复制给 AI (Copy for AI) produces a prompt containing the source location, latest generated download, document ID, revision, block ID, paragraph position, and current content. Selection, image, block, and document entry points use their respective scope. Users append the requested change in their own AI tool. The prompt omits image encoding and editor code; the document does not retain a local filesystem path.

The CLI supports structured processing of both file forms:

sh
node cli.mjs inspect dist/service.pai.html
node cli.mjs inspect dist/service.pai.html offer-b
node cli.mjs asset dist/service.pai.html hero -o hero.svg
node cli.mjs convert dist/service.pai.html -o service.pai
node cli.mjs inspect service.pai
node cli.mjs patch service.pai change.json -o edited.pai
node cli.mjs convert edited.pai -o edited.pai.html
node cli.mjs hash edited.pai

inspect includes text and asset descriptions while omitting image encoding and the editor program. A container-only conversion preserves the document ID, revision, blocks, and every image. A successful content patch increments the revision. File writes use a temporary file and replace the target only after the write succeeds.

Converting ZIP to HTML uses dist/service.pai.html as the default complete editor template. Specify another complete template with --template template.pai.html. An HTML input uses its existing shell by default. The template must carry the styling and code needed to run independently; the data parser verifies the content entry point rather than executing the template.

Patch operations are applied as one batch against baseRevision. Supported operations are replaceRegion, setBackground, moveRegion, insertRegion, deleteRegion, setLayout, reorderRegions, reorderSections, and setBackgroundImage. For example, save this as change.json for a document at revision 0 with an intro block and hero asset:

json
{
  "baseRevision": 0,
  "operations": [{
    "type": "setBackgroundImage",
    "id": "intro",
    "image": {"asset":"hero","x":50,"y":50,"overlay":0.65,"shade":"#ffffff"}
  }]
}

Use "image": null to remove a background image. A stale baseRevision or an invalid operation rejects the whole patch.

The browser and Node implementation share these limits: 64 MiB input or total expanded ZIP data, 4,096 ZIP entries, and JSON nesting depth 256. Python is used for independent ZIP checks in tests; production file processing does not require it.

Content representation ​

A .pai ZIP stores document.json and original image entries. The authoritative data in .pai.html is the JSON in <script id="pai-data" type="application/json">. Both forms use block Markdown, ordered layout arrays, and a shared asset table. The local tools can migrate legacy 0.4 and 0.5 HTML data on import; publication requires content model 0.6.

An image instance can carry a placement ID, width percentage, and alignment:

md
![Image description](pai:hero){pai-image:img_one width=60 align=center}

The same asset can appear at different widths and positions. A block's backgroundImage stores its asset ID, crop focus, overlay opacity, and overlay color. An empty paragraph is represented by <!--pai:blank--> on a line of its own. See the format specification for field definitions and validation rules.

Development checks ​

From the project root, run npm run verify for file, specification, and service checks. The browser acceptance suite exercises editing, file conversion, publication, and historical reads. Historical measurements record file sizes from the earlier three-document run. Independent tester tasks and reports are in development/.
