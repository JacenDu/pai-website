The PAI protocol ​

PAI defines how personal AI applications publish, update, and retrieve content through a service. Its current content profile gives clients a shared way to find operations, upload documents, read published material, and retain source links.

Who implements what ​

ParticipantRole
Host applicationThe tool or Harness in which a person works with their AI. It uses a PAI client.
PAI clientDiscovers a service and carries out publication or retrieval operations.
PAI serverImplements the content interfaces within a service. It validates uploads, checks ownership, and exposes published versions.
Service providerOperates the server and supplies the account system, storage, and product interface.

The same selected service receives publication requests and serves content to readers. A platform can implement these interfaces alongside its existing services. Follo is one potential provider.

Publish, update, retrieve ​

A client starts at /.well-known/pai.json. The service descriptor advertises supported capabilities, accepted file formats, and endpoint URLs.

Publish. The client sends a complete .pai or .pai.html file with a publisher credential. The server validates it, stores a publication version, and returns its resource and representation URLs.

Update. The owning publisher submits a changed document to the resource's update URL. A new document revision creates another stored publication version. Repeating the same revision and content returns the existing snapshot.

Retrieve. A reader selects a resource from the catalogue or uses a known resource URL. Structured content provides ordered Markdown blocks, image metadata, and source links. The complete file supplies original image bytes when needed.

Keep the source tied to its version ​

Document IDs travel with files. A document revision records content edits. The service assigns its own resource ID and publication version.

Each returned block has a sourceUrl pointing to its location in a particular published snapshot. A later update preserves that earlier source. Clients can retain document, publication, block, and asset identifiers when reusing material.

Publication and updates use Bearer credentials. Published content is publicly readable under the current profile. The service determines ownership from the credential.

Build against the current draft ​

The reference implementation includes publication and retrieval clients, an HTTP server, and a command that checks a service through its advertised interfaces.

  • Client integration: connect an AI application or Harness.
  • Server integration: implement the content profile in a platform.
  • Specification overview: read normative requirements, schemas, and fixed examples.

The current protocol is 0.1.0-draft.1. The specifications are maintained in English; this page is an introduction.

Planned extensions ​

Query-based retrieval will build on published versions, block identifiers, and source URLs to return relevant material for a request. Hosted-agent work will define how a service operates an outward-facing agent within a user's authorized scope. Both extensions are planned; their message formats remain to be specified.
