PAI Content Protocol ​

Protocol 0.1.0-draft.1 · Profile content

PAI clients publish, update, and retrieve documents through a selected service. The server validates uploaded files, enforces publisher ownership, stores publication versions, and exposes their content and original files.

Participants ​

  • Host application: an AI application or Harness that uses a PAI client.
  • Client: discovers service capabilities and issues publication or retrieval requests.
  • Server: implements the content interfaces within a service. The service provider operates its accounts, credentials, storage, and user interface.

HTTP operations ​

OperationRequest targetResult
DiscoverGET /.well-known/pai.jsonCapabilities, formats, authentication scheme, and endpoint URLs
PublishPOST endpoints.documentsA resource and its publication version
UpdatePUT resource.updateUrlA new version or the matching stored snapshot
List resourcesGET endpoints.resourcesLatest resource metadata in an items array
Read contentGET representations.contentresource, document, ordered blocks, and assets
DownloadGET representations.downloadThe original file stored for that version

Clients follow URLs returned by discovery and resource responses. Publication and updates send the complete .pai or .pai.html file as raw request bytes.

Writes use Authorization: Bearer <credential>. The server derives the publisher identity from that credential. Discovery and published content are publicly readable. Network deployments use HTTPS; loopback development services may use HTTP.

Identifiers and versions ​

document.id identifies the document across file forms. Its integer revision increments when content changes. The service assigns a resource ID and a publication version starting at "1".

A higher document revision creates the next publication version. Repeating the same revision and content returns the stored snapshot with 200, including for a historical revision. Reusing a revision with different content returns 409 document_revision_conflict. An older revision that has never been published returns 409 stale_document_revision.

Each returned block contains id, markdown, and sourceUrl. The source URL identifies the block in a specific publication snapshot. Subsequent updates preserve earlier text, original images, and source URLs. Image bytes are extracted from that version's downloaded file using the asset ID and declared packaging format.
