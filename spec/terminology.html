PAI Terminology ​

2026-11-09 · Informative vocabulary for the content protocol and file format.

Participants ​

PAI client: a program that sends PAI requests and processes responses. It can be part of a personal AI application, a command-line tool, or a web backend.

PAI server: a program that implements PAI endpoints. The content profile defines discovery, publication, updates, retrieval, and file downloads. A server can consist of one process or several components. Client and server describe communication roles, following the terminology of HTTP, RFC 9110 §3.3.

Service provider: the organization or person operating a PAI service. Use “server” for protocol behavior and “service provider” for deployment, accounts, operations, and commercial integration. Follo or an individual operator can run a PAI server.

Host application: the user-facing application or runtime containing a PAI client. “Harness” describes an agent execution and tool-orchestration environment in implementation documentation. Protocol requirements apply to the client that sends the requests.

Agent: an AI system that performs tasks and calls tools for a user. A personal agent can access a PAI service through a client. A hosted agent is an agent operated by a service to respond within a user's authorized scope. Hosted-agent authorization and interaction rules are planned extensions.

Publication identity ​

Publisher: the principal identified by the server from a credential and authorized to manage the resulting published resources. The server returns this identity in publisherId.

Author: the creator or credited author of the content. Authorship can be expressed in document content or associated metadata. An author name in a file does not grant publication permissions.

Publisher identifiers are local to a service. Credential issuance is managed by the service provider. The content profile uses Bearer credentials for authenticated writes; SERVICE.md defines authentication and ownership checks.

The term “resource” denotes an addressable object, and “representation” denotes its transferred form, consistent with RFC 9110 §3.1–3.2. A PAI content hash supports comparison and retry handling; it is not a publisher credential or a digital signature.
