PAI 内容协议 ​

协议版本 0.1.0-draft.1 · Profile content

PAI 客户端通过所选服务发布、更新和读取文档。服务端验证上传文件，检查发布权限，保存发布版本，并提供对应内容及原始文件。

参与者 ​

  • **宿主应用：**使用 PAI 客户端的 AI 应用或 Harness。
  • **客户端：**发现服务能力，发送发布或读取请求。
  • **服务端：**在服务中实现内容接口。服务提供者负责账号、凭据、存储和用户界面。

HTTP 操作 ​

操作请求目标返回内容
服务发现GET /.well-known/pai.json能力、格式、认证方式和接口地址
发布POST endpoints.documents资源及其发布版本
更新PUT resource.updateUrl新版本或已保存的匹配版本
资源目录GET endpoints.resourcesitems 数组中的最新资源信息
内容读取GET representations.contentresource、document、按顺序排列的 blocks 和 assets
文件下载GET representations.download该版本首次保存的原始文件

客户端使用服务发现和资源响应中返回的地址。发布和更新以完整 .pai 或 .pai.html 文件的原始字节作为请求体。

写入请求使用 Authorization: Bearer <credential>。服务端根据凭据确定发布者身份。服务发现和已发布内容可公开读取。网络部署使用 HTTPS，本地回环开发服务可使用 HTTP。

标识与版本 ​

document.id 标识不同封装中的同一文档。整数 revision 随内容编辑递增。服务分配资源 ID，发布 version 从 "1" 开始。

更高的文档修订号产生下一个发布版本。同一修订和内容再次提交时，返回 200 和已保存的版本，历史修订同样适用。同一修订对应不同内容时，返回 409 document_revision_conflict。未曾发布的旧修订返回 409 stale_document_revision。

返回的每个内容块包含 id、markdown 和 sourceUrl。来源地址指向具体发布版本中的内容块。后续更新保留旧版本的文字、原图和来源地址。客户端下载该版本的文件，再按图片 ID 和声明的封装格式提取图片字节。
