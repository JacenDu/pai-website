PAI 协议 ​

PAI 约定个人 AI 应用怎样通过服务发布、更新和读取内容。当前内容协议让客户端用共同的方式发现接口、上传文档、取得素材，并保留来源链接。

谁负责哪一部分 ​

参与者职责
宿主应用人和自己的 AI 使用的工具或 Harness，通过 PAI 客户端接入服务。
PAI 客户端发现服务接口，执行发布或读取操作。
PAI 服务端在服务中实现内容接口，验证文件、检查发布权限、提供历史版本。
服务提供者运行服务端，提供账号、存储和产品界面。

所选服务同时接收发布和读取请求。平台可以把这些接口接入现有系统。Follo 是潜在的服务提供者之一。

发布、更新、读取 ​

客户端从 /.well-known/pai.json 开始，取得服务支持的能力、接受的文件格式和接口地址。

发布。 客户端带上发布凭据，上传完整的 .pai 或 .pai.html 文件。服务端验证文件，保存一个发布版本，并返回资源及其不同读取形式的地址。

更新。 发布者把修改后的文档提交到该资源的更新地址。新的文档修订产生新的发布版本。同一修订和内容再次提交时，返回已经保存的版本。

读取。 读者从目录中选择资源，或直接使用已知资源地址。结构化内容提供按阅读顺序排列的 Markdown 内容块、图片信息和来源链接。需要原图时，再取得完整文件中的图片字节。

来源跟随具体版本 ​

文档 ID 随文件保存，文档修订号记录内容编辑。服务为已发布文档分配资源 ID 和发布版本号。

每个返回的内容块都有 sourceUrl，指向某个发布版本中的具体位置。后续更新仍保留这个旧版本。客户端复用素材时，可以同时保存文档、发布版本、内容块和图片的标识。

发布和更新使用 Bearer 凭据。当前协议中的已发布内容可公开读取。服务根据凭据确定发布权限。

接入当前草案 ​

参考实现提供发布客户端、读取客户端、HTTP 服务端，以及通过声明接口检查服务的命令。

  • 客户端接入（英文）：让 AI 应用或 Harness 使用 PAI 服务。
  • 服务端接入（英文）：在平台中实现当前内容协议。
  • 规范总览（英文）：查看规范要求、数据结构和固定样例。

当前协议版本为 0.1.0-draft.1。正式规范以英文维护，本页用于说明项目及接入思路。

后续扩展 ​

查询检索将利用已有的发布版本、内容块标识和来源链接，按请求返回相关素材。托管代理部分将约定服务如何在用户授权范围内运行对外代理。这两项属于后续规划，通信格式待制定。
